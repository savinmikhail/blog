# Независимое техническое ревью редакционной версии

Дата: 2026-10-16. Проверены `article.md`, `example/README.md`, `compose.yaml`, `app/config-values.php`, `app/config.php`, `check.py`, `dotenv-probe.php`, composer lock и локальный исходник Symfony Dotenv 7.4.18. Это ревью редакционной версии после перехода к сквозному примеру; более ранние ревью относятся к своим снимкам.

## Замечание, которое стоит исправить до публикации

### P2 — Связать Symfony dump-env с bootstrap выбранного примера

В главе 3 выбран `(new Dotenv())->loadEnv(...)`, а глава 5 предлагает `composer dump-env prod` и затем говорит, что «стандартный bootstrap» использует дамп. Читатель, последовательно повторяющий именно наш standalone PHP-пример, не получит этого поведения: установлен только `symfony/dotenv`, команды Symfony Flex нет, `loadEnv()` сам `.env.local.php` не читает. Это не ошибка утверждения о стандартном Symfony-проекте, а пропущенный переход между двумя способами запуска.

Достаточное исправление: явно сказать, что команда относится к Symfony-проекту с соответствующим Composer/Flex bootstrap, показать `bootEnv()` для standalone-загрузчика, который должен учитывать `.env.local.php`, и обозначить, что итоговая CLI-лаборатория специально продолжает использовать текстовые файлы. Полноценный кеш или Flex в лабораторию добавлять ради этого не требуется.

Основание: установленный `Dotenv.php` 7.4.18, методы `loadEnv()` и `bootEnv()`; [Symfony configuration 7.4](https://github.com/symfony/symfony-docs/blob/7.4/configuration.rst), [исходник Dotenv 7.4.18](https://github.com/symfony/dotenv/blob/v7.4.18/Dotenv.php).

## Что проверено и работает

- `python3 check.py`: 13 поведенческих сценариев прошли на PHP 8.5.9. Проверены defaults, process override, ошибочные значения, отсутствие и пустота секрета, обе boolean-ветки, точный DSN со спецсимволами, отсутствие пароля/DSN в stdout/stderr и отсутствие их экспорта через `putenv`.
- `TMPDIR=/private/tmp php dotenv-probe.php`: Symfony Dotenv v7.4.18 вернул `local` и `https://local/path`, т.е. зависимое значение пересобралось после local override. Утверждение главы 6 соответствует этой конкретной версии и опыту.
- Отдельный синтетический запуск на копии `app/` с незакрытой кавычкой и маркером секрета в `.env`: exit 1, пустой stdout, stderr только `Configuration could not be loaded`; маркер не раскрыт. Проверяемый исходный пример для этого не менялся.
- `DB_PASSWORD_FILE` реализован приложением; файл читается, URI-компоненты user/password кодируются отдельно, порт и имя БД валидируются. Код не выдаёт паролю способность автоматически работать в произвольном образе.
- Главы про секреты и LLM сохраняют границы: file delivery не отбирает возможность чтения у процесса, 0600 не изолирует от владельца, маска вывода не является ACL, настоящий ключ нельзя защитить от произвольного кода, запущенного с доступом к нему.
- Указанные исправления JSON5 1.0.2/2.2.2 и python-dotenv 1.2.2 сверены с первичными GitHub advisories. Статья верно ограничивает условия эксплуатации и не объявляет обычное чтение env универсальным RCE. [JSON5 advisory](https://github.com/json5/json5/security/advisories/GHSA-9c47-m6qq-7p4h), [python-dotenv advisory](https://github.com/theskumar/python-dotenv/security/advisories/GHSA-mf9w-mj56-hr94).
- Формулировки про Unleash PHP TTL/stale-cache и Compose file secrets соответствуют текущим первичным документам. Статья не обещает мгновенное обновление флага и не приписывает Compose шифрование source-файла. [Unleash PHP](https://docs.getunleash.io/sdks/php#caching), [Compose services](https://docs.docker.com/reference/compose-file/services/#secrets).

Docker runtime повторно не запускался этим ревьюером; его проверяет основной агент. Полные Symfony/Laravel приложения, Postgres connection, Kubernetes и flag provider этим CLI не проверяются; границы в статье и README названы.

## Неблокирующие пожелания

1. Добавить синтетическую malformed-dotenv проверку в `check.py`, чтобы нераскрытие parser error сохранялось как регрессия, а не только как ручная проверка ревьюера. Полезен также явный nonexistent path к secret file; текущий `missing_secret` проверяет пустой путь.
2. Пример не запрещает все имена host по полной DNS-грамматике и не подключается к БД. Это честно названо в README; не расширять `valid` в статье до обещания доступности сети/успешной аутентификации.

После короткого пояснения `loadEnv`/`bootEnv` технических блокеров для текущей формы статьи не вижу.
